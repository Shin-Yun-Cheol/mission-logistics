## Mission Overview

프로그램을 실행할 경우 수시로 배송을 요청할 수 있다. 배송을 요청할 경우 5주차 미션의 예측 시스템만큼의 시간 후에 배송이 완료되었다는 안내를 출력한다. 차량이 배송 출발지로 이동하는 시간은 고려하지 않는다. 현실에서의 3분을 시뮬레이션에서 1초로 가정한다.
## Feature Requirements Details

5주차에 구현한 프로그램을 바탕으로 출발지와 도착지, 주문자를 입력하면 배송을 시뮬레이션하고 배송이 완료된 후에 터미널로 안내 메시지를 전송한다. 출발지와 도착지, 주문자는 `출발지-도착지(주문자)` 와 같은 양식으로 입력받는다. 배송이 접수된 후 곧바로 배송이 시작되며 예측 시간의 3분당 실제 시간의 1초정도의 지연이 발생한 후 배송 완료 안내 메시지를 보낸다. 이 때 구분을 위해 배송 id를 포함한다. 배송 id는 배송을 구분하기 위해 존재하며 1부터 시작해서 매 배송마다 1씩 증가한다.

```bash
배송 정보를 입력해 주세요. ex)봉화군청-숭실대학교 정보과학관(박호건)
> 봉화군청-숭실대학교 정보과학관(박호건)
배송이 정상적으로 접수되었습니다. (id: 1)
배송이 시작되었습니다. (id: 1, 예상 배송 시간 : 3시간 10분)
배송이 완료되었습니다. (id: 1)

배송 정보를 입력해 주세요. (ex. 봉화군청-숭실대학교 정보과학관(박호건)
> ...
```

해당 예시에서는 배송이 동기적으로 처리되었으며 배송이 시작된 후 약 1분 3초 정도의 시간이 지난 후 `배송이 완료되었습니다.` 메시지를 띄운다.

(응용 1) 시뮬레이션을 비동기적으로 구현한다. 운송차량의 수는 무한하다고 가정한다.

(응용 2) 운송차량은 5대까지 존재한다. 운용할 수 있는 차량을 넘어서는 주문이 접수될 경우 대기 후 배송한다.

(심화 1) 사용자가 입력하기 편하게 터미널을 관리한다.

- ex) 사용자가 입력 중에 출력 요청이 있을 경우 입력이 종료된 후 출력을 진행한다.

(심화 2) 다음 두 조건을 만족하는 통합테스트를 구현한다.

- 대기 시간을 엄밀히 테스트한다. (근사값으로 테스트를 검증하지 않는다. )
- 통합테스트에 소요되는 시간을 최소화한다.
